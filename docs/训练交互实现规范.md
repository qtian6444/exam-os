## 1. 本轮只补两件事

现有工程已具备 ChoiceCard / ReorderCard / ReadingBreakdownCard、逐题提交、证据写入、能力更新、Result、下一题流程。

本轮只补：

1. 统一逐题 `FeedbackPanel`；
2. 错误后的「重试 → 解析 → 同类强化」闭环。

必要时增加统一 `TrainingFlow` 状态层。**不得**借此改 Auth、RLS、RPC、数据库、`saveExecutor` 或现有能力 owner。

---

## 2. 统一 TrainingFlow 状态机（核心新增）

```
answering → checking → correct → completed

answering → checking → hint → retry → correct → reinforcement/completed

retry → checking → explained → reinforcement → completed
```

| 状态 | 含义 | 允许的主要操作 |
| --- | --- | --- |
| `answering` | 初次作答 | 选择、排序、输入、提交 |
| `checking` | 判题与防重复提交 | 无，按钮禁用 |
| `correct` | 当前作答正确 | 查看简短正反馈、继续 |
| `hint` | 首次错误后的局部提示 | 查看错误位置，不显示完整答案 |
| `retry` | 同题再次尝试 | 修改答案并重新提交 |
| `explained` | 达到最大尝试后揭示解析 | 查看正确答案、原因和能力映射 |
| `reinforcement` | 一道同类强化或简化验证 | 作答、获得支架后继续 |
| `completed` | 本题闭环完成 | 下一题 |

### 尝试次数（MVP 默认）

- 第一次错误：不给完整答案；
- 第二次仍错：给完整解析；
- 随后进入一题同类强化或后续验证。

### 防重复提交

`checking` 期间禁用提交。**每次尝试必须有唯一 `attemptIndex`**，证据写入不得因快速点击而重复。

## 3. 统一 FeedbackPanel（三要素）

每次错误反馈固定三要素：

1. **为什么错**：一句与题型规则对应的原因；
2. **错在哪**：对具体选项 / 碎片 / 字符 / 匹配对做视觉定位；
3. **下一步练什么**：映射到现有五维能力 + 一个具体动作。

示例：

```text
为什么错
你把修饰语放到了主句前面，句子主干被拆开了。

错在哪
第 2、3 个词块位置互换。

下一步练什么
继续练习 sentence：先找主语和谓语，再放修饰语。
```

### 反馈来源（只允许）

题目配置、题型规则、用户答案与正确答案的差异、固定模板、现有五维能力映射。**禁止**为逐题反馈新增自由生成式 LLM 依赖。

### 首次错误 vs 第二次错误

| 阶段 | 显示 | 不显示 |
| --- | --- | --- |
| 首次错误 | 错误状态、具体错误位置、一句局部规则提示、「再试一次」 | 完整正确序列、完整参考答案、长期能力诊断 |
| 第二次错误 | 正确答案、为什么正确、用户答案与正确差异、对应能力、下一道同类强化 | — |

正确反馈简短、具体，无空洞鼓励，无「能力提升 X%」（无数据时）。

### 视觉定位表

| 题型 | 错误定位 |
| --- | --- |
| 选择 | 标出用户选择；首次错误不必同时点亮正确项 |
| 排序 | 标出错位碎片与目标位置关系 |
| 文本 | 标出首个差异及相邻差异字符/单词 |
| 匹配 | 标出错误配对两端 |
| 阅读 | 高亮应定位的原文证据区域或段落 |

## 4. 三张现有卡片落地规则

### ChoiceCard

- 用户未选择前提交不可用；
- 首次错误：保留用户选择、标出错误、显示题型提示、**不立即高亮正确项**、「再试一次」后解除选项锁定；
- 第二次错误：高亮正确选项、对比干扰项与正确项、三要素反馈、进入同类强化或继续。

### ReorderCard

- 点选/拖拽都能稳定改变序列；点选在「未使用 ↔ 已排列」间移动，拖拽调整顺序；
- 判题按稳定 ID 逐位比较，不按显示文本猜测；需返回第一个错位位置及全部错位索引；
- 首次错误：高亮错位碎片 + 规则提示（先找主句 / 修饰语紧跟被修饰词），不自动排成正确句；
- 第二次错误：展示正确序列、标出第一个错误位置、解释主干与修饰、进同结构强化。

### ReadingBreakdownCard

- 支架型，不强行计分；先展示原句、用户先自读、「逐步拆解」**一次只展开一层**；
- 记录用户用了哪一级支架、是否完成拆解、之后能否无支架完成配套任务；
- 「点了我理解了」≠ 掌握；拆解完成后进入同一句排序/翻译/主干识别/证据定位验证。

---

## 5. 强化闭环与兜底

标准错误路径：

```
第一次错误 → 定位 + 一句规则提示 → 同题重答/简化重答
→ 第二次仍错 → 完整解析 + 正确答案 + 能力映射
→ 一题同类强化/后续验证 → 记录证据并继续
```

- 强化题优先与原题共享可解释结构（同句法关系 / 同词根易混音 / 同定位策略 / 同逻辑连接 / 同拼写规律），不是随机再来一题。
- 强化题不能成为无限通关墙；强化仍错时提供必要帮助或揭示并允许继续，记录为待后续验证。
- **无强化题时**：不随机选题，解析后记录 `PENDING_VALIDATION`，交后续 Decision 决定何时验证。
- 支架强度 S0–S5，不机械逐级播放，选当前最低必要支架。

---

## 6. 文案准则

按钮推荐固定标签：`提交` `再试一次` `查看解析` `继续` `下一题` `逐步拆解` `我来试试`。
避免：`点击查看答案` `我不会，直接告诉我` `AI 自动帮你完成`。

反馈语气具体、短、可执行；说「这道题你定位到了干扰段」，不说「你的阅读定位能力很差」。

---

## 7. 异常与边界状态

| 场景 | 处理 |
| --- | --- |
| 未选择 / 空答案 | 提交按钮禁用；键盘触发则局部提示，不记为能力错误 |
| 网络 / 保存失败 | 判题可本地完成，但保存失败必须显示可重试；未保存结果不得表现为已长期记忆 |
| 退出 | 合法，不是答错；是否保存按现有会话规则 |
| 题目配置错误 | 缺正确答案/反馈规则/能力映射时该题不进训练，显示可恢复错误，不判用户错 |
| 无强化题 | 记录 `PENDING_VALIDATION`，不随机选题 |
| Breakdown 服务不可用 | 用静态拆解/兜底；无可靠内容则提示稍后重试，不制造解析 |

## 8. 数据契约（产品层字段，不要求一比一新增列）

```ts
type AbilityDimension =
  | 'vocabulary' | 'sentence' | 'reading' | 'listening' | 'writing'

type QuestionType =
  | 'choice' | 'reorder' | 'text' | 'matching' | 'reading_breakdown'

interface TrainingQuestion {
  id: string
  type: QuestionType
  module: string
  title: string
  prompt: string
  dimensions: AbilityDimension[]
  contentSource?: 'CET_REAL' | 'TRUSTED_TEACHING' | 'GENERATED'
  options?: Array<{ id: string; label: string }>
  blocks?: Array<{ id: string; text: string }>
  correctAnswer?: unknown
  acceptedAnswers?: string[]
  feedback: {
    rule: string
    firstHint: string
    nextPractice: string
  }
  reinforcement?: {
    mode: 'same' | 'simplified' | 'similar'
    questionId?: string
  }
}

interface RuleFeedback {
  correct: boolean
  attemptIndex: number
  why: string
  where: Array<{
    kind: 'option' | 'block' | 'character' | 'pair' | 'evidence_span'
    id?: string
    index?: number
    message: string
  }>
  next: string
  dimensions: AbilityDimension[]
  revealAnswer: boolean
}
```

证据写入每次尝试至少保留：`questionId`、`attemptIndex`、用户答案、正误、支架级别、是否揭示答案、真实 elapsed time、能力维度、事件时间。**辅助后正确与无提示独立正确不能记录成同一种证据。**

## 9. 验收用例（节选）

- Choice：未选择不能提交；正确只写一次证据；首次错误不揭示正确答案；再试可改答案；二次错误显示正确答案+三要素；快速重复点击不重复保存。
- Reorder：点选/拖拽稳定改变序列；按稳定 ID 判题；首次错误标出具体错位；重试保留可编辑；二次错误显示正确序列并进强化。
- ReadingBreakdown：先见原句；一次只展开一层；「我理解了」不写掌握；拆解后进无支架验证。
- FeedbackPanel：三要素来自题目规则和真实差异；不出现无来源能力百分比；移动端底部层不遮按钮。
- 强化：一错→提示→重试；二错→解析→强化；强化仍错不锁死；达到最大尝试后允许继续并留待验证证据。
- 回归：Auth 不变；RLS/RPC/DB 无变更；`saveExecutor` 不变；Dashboard/Result 仍可读能力数据；`test`/`typecheck`/`lint`/`build` 全过。
